Paula Abbey Counselling — transferring ownership

A step-by-step guide for transferring the site, its hosting, and its code repository into your ownership.

Who this guide is for

This document is for the developer taking over maintenance of the Paula Abbey Counselling website. It covers the one-time transfer of ownership only — for ongoing reference about how the site is built and maintained, see the README.md in the code repository.

Work through the steps in order. Some of them need to happen at specific points relative to others, so skipping ahead can cause brief outages.

What you're taking on
Context for the rest of the guide

The website is built with Gatsby (a React-based static site generator), hosted on Netlify, with the code in a private GitHub repository (paula-abbey). There is no CMS: page content and layout live in the codebase, not in an admin panel. Wording or structural changes are made by editing the repository and deploying.

Contact form submissions go through Netlify Forms and arrive by email. There is no database. Each deploy rebuilds the entire site from the code and publishes the new version. This takes around a minute or two per build.

ℹ
The README has the detail For a full explanation of the stack, how to run it locally, and how to maintain it, read README.md in the repository. This guide focuses only on getting ownership transferred cleanly.
!
Domain registrar is separate from DNS hosting The domain paulaabbey.co.uk is currently registered in Gideon's Ionos account and still needs to be transferred into an Ionos account in Paula's name. DNS is managed in Netlify (and moves with the site in step 3). Ionos only needs to keep the domain's nameservers pointed at Netlify. Step 5 covers the registrar handover.
✓

The handover, step by step
1
Create the accounts you'll need
You do this — 5 to 10 minutes You do this

You'll need a GitHub account and a Netlify account. If you already have personal ones you're comfortable using for this, they're fine. Otherwise, create them now.

  • GitHub account Sign up at github.com/signup. A free personal account is sufficient. Make a note of the username — you'll need to share it in step 2.
  • Netlify account Sign up at app.netlify.com/signup. You'll be prompted to create a team — a free Starter team is fine. Sign up using your GitHub account if you want; it makes later steps slightly smoother.
  • Share both with Gideon He'll need your GitHub username (for the repo transfer) and the email address on your Netlify account (for the site transfer).
2
Receive the GitHub repository
You do this — a few minutes You do this

Gideon will initiate a repository transfer from his GitHub account to yours. You'll receive an email from GitHub asking you to accept.

  • Accept the transfer Open the email from GitHub and click the link to accept. Alternatively, log in to GitHub and look for the pending transfer notification at the top of your dashboard.
  • Confirm the repo appears in your account The repository should now be at https://github.com/<your-username>/paula-abbey. All commit history, branches, and settings come with it.
ℹ
The repo name stays as paula-abbey If you rename the repository later, update any references in Netlify's build settings and anywhere else the old name appears.
3
Receive the Netlify site
You do this — a few minutes You do this

Once your Netlify team exists (step 1), Gideon will transfer the Netlify site into it. You'll receive an email and an in-app notification when the transfer is ready to accept.

  • Invite Gideon to your Netlify team From your new Netlify team, invite Gideon so he can initiate the site transfer into your account. You'll coordinate separately on which email address to use and what role to assign — the details aren't fixed in this guide.
  • Accept the transfer in Netlify Log in to Netlify and look for the pending transfer notification, or follow the link in the email. Confirm acceptance.
  • What moves across automatically Deploy history, the live site, custom domain and Netlify DNS (DNS zone and records), Netlify Forms submissions, form notification settings, and build settings. Essentially, the site continues running as it did, just under your account.
  • One thing that doesn't move The connection between the Netlify site and the GitHub repository. That's reconnected in step 4. Until then, the site is still live — new commits just won't trigger builds.
✓
No DNS reconfiguration in this step Because the domain uses Netlify DNS, the DNS records come with the site transfer. Nameservers at Ionos should already point at Netlify and don't need changing for steps 3 and 4.
ℹ
Ionos is not part of the Netlify transfer Domain registration at Ionos stays in Gideon's account until step 5. The site should remain reachable throughout steps 3 and 4.
4
Reconnect the GitHub integration
You do this — a few minutes You do this

Netlify needs permission from your GitHub account to read the repository and trigger builds when you push commits. This permission is user-specific, so it needs re-authorising under your account.

  • Open the site's build settings in Netlify In the transferred site, go to Site configuration → Build & deploy → Continuous deployment. You should see a prompt to reconnect or reauthorise GitHub access.
  • Authorise Netlify on GitHub Follow the prompts. You'll be bounced to GitHub to approve the Netlify app for your account and grant it access to the paula-abbey repository. Approve it.
  • Trigger a test build Back in Netlify, go to Deploys and click Trigger deploy → Deploy site. Watch the build log. If it completes successfully, the integration is working.
5
Transfer the domain to Paula (Ionos)
Coordinated with Gideon and Paula Coordinated

The domain paulaabbey.co.uk should be registered and renewed in Paula's own Ionos account, not Gideon's. Gideon will start the Ionos transfer once Paula has an account ready. You do not need to recreate DNS records in Ionos — DNS stays on Netlify (step 3). After the domain moves between Ionos accounts, check that Ionos still lists Netlify's nameservers for the domain.

!
Check nameservers after the Ionos transfer Moving a domain between Ionos accounts can sometimes reset or change nameserver settings. In Paula's Ionos account, confirm the domain still uses Netlify's nameservers (the same values as before the transfer). If they were changed, point them back to Netlify before considering step 5 complete.
  • Paula has an Ionos account in her name Paula creates or identifies the Ionos login that should own the domain going forward. She shares the contact email Ionos needs with Gideon so he can initiate the transfer from his account.
  • Gideon initiates the domain move From his Ionos account, Gideon starts the transfer of paulaabbey.co.uk to Paula's Ionos account, following Ionos's on-screen process (auth codes or approval emails as required).
  • Paula accepts and confirms ownership Paula completes any acceptance steps in Ionos. Once finished, she — not Gideon — receives renewal reminders and controls the domain registration.
  • Confirm nameservers still point at Netlify In Paula's Ionos domain settings, verify the nameservers are still Netlify's (not Ionos defaults). Compare with the nameservers shown in Netlify under Domain management for the site if needed. The live site and HTTPS should keep working once this is correct.
6
Verify everything works
You do this — 15 minutes You do this

Before calling the handover complete, run through this checklist end-to-end. If anything fails, stop and troubleshoot before moving on.

  • The live site loads Visit https://paulaabbey.co.uk in a browser. Check the homepage and main sections (About, Services, Appointments, FAQ, and any other linked pages). Test on a phone as well as a desktop.
  • A code change triggers a build Clone the repository locally (or edit a file on GitHub), make a trivial change, commit, and push. Watch the Netlify Deploys tab — a new deploy should start within seconds and complete successfully.
  • Contact form submission arrives Submit the contact form on the live site with test content. Confirm the submission appears in Netlify under Forms, and that the notification email reaches Paula (or the address configured in Netlify).
  • Domain and SSL The site loads over HTTPS with a valid certificate. In Netlify Domain management, the custom domain is primary and HTTPS is enabled.
  • Domain is in Paula's Ionos account Paula can log in to Ionos and see paulaabbey.co.uk under her domains, with nameservers still pointing at Netlify. Gideon no longer needs to renew it on her behalf.
✓
If everything above passes, the handover is complete You own the code and hosting on your GitHub and Netlify accounts. Paula owns the domain at Ionos. Nothing critical remains tied to Gideon's accounts.
After the handover
✓
Ongoing responsibilities
What's now on your plate
  • Hosting costs Netlify's Starter plan is free and handles this site's traffic comfortably. Upgrade if traffic grows or you need additional Netlify features.
  • Domain renewal Once step 5 is complete, Paula renews paulaabbey.co.uk through her Ionos account. Keep those login details safe.
  • Content updates There is no CMS. Copy and layout changes go through the repository and a deploy. Agree with Paula how she'll request updates and how quickly you'll ship them.
  • Security of your accounts Enable two-factor authentication on both GitHub and Netlify. The site's source code and hosting are accessible through those accounts.
  • Ongoing maintenance Gatsby, Node, and other dependencies will need periodic upgrades. Use the README as the living technical reference and schedule upgrades at a pace you're comfortable with.

If anything in this guide is unclear, or if a step doesn't behave as described, reach out before proceeding — a short conversation is much cheaper than an unexplained outage.
